## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make lore's OKF type system PROFILE-DRIVEN via a declarative per-project .lore/profile.toml (D1; FINALIZED against ECK's 17-type SDD draft — lore's first external consumer). The profile is the source of truth; lore GENERATES its runtime validators + Draft-7 editor JSON-Schemas from it at load (inverts ADR-0006: declarative profile -> generated Zod -> z.toJSONSchema). No code, no embedding, no escape hatch — the declarative language is the boundary. lore ships a built-in default story-convention profile; a missing profile.toml is NOT an error (zero-config still works). lore bundles NO consumer profile (ECK ships its own in its repo).

FINALIZED GRAMMAR (TOML at .lore/profile.toml; .lore/profile.json permitted as identical-semantics secondary, profile.toml wins; COMMITTED; separate from config.toml):
- [profile]: name (req), okf_version (req; asserted vs bundle-root index.md), case (opt, default 'Title'; powers the unknown-type 'did you mean' hint, never coerces), resource_base (opt, default ''; drives lore new resource stamping per LORE-47).
- [base.fields]: fieldName -> inline-table field-spec; fields every type carries. 'type' MUST be { required = true } (OKF's one hard requirement).
- [[types]] array-of-tables (TOML key is 'types' not 'type', to avoid colliding with the OKF type frontmatter key): name (req; the OKF type value), fields (table; ADDED to base, or override a base field by re-declaring its name — FULL REPLACE, e.g. FRD/Spec promote 'feature' to required), sections (array of required body headings), template (filename under .lore/templates/).
- Field-spec = inline table; {} = optional string. Attrs: required (bool, default false); kind (string|list|datetime|number|boolean|integer, default string; named 'kind' NOT 'type' to avoid the OKF-key collision — adopting ECK's choice); enum (string array -> closed set, implies kind=string, EXACT case-sensitive match); items (list element spec); default (editor-advertised only, NEVER stamped — preserves byte-stability).
- sections matched by heading TEXT (trimmed, case-sensitive) at depth <=2, array order NOT enforced; missing required section = Tier-2 error for a known type (body-only mdast pass, ADR-0007).
- Unknown handling: unknown TYPE -> Tier-3 warn (lenient passthrough); unknown FIELD -> byte-identical passthrough + Tier-3 warn on a known type only (editor schema additionalProperties:true); unknown PROFILE key -> load warning, ignored; duplicate type name / enum+non-string kind / malformed table -> load ERROR.
- Generated artifacts: each type -> .lore/schemas/<slug>.json + yaml-language-server modeline, where <slug> = LOWER-KEBAB of the type name ('QA Plan' -> qa-plan.json, matching its qa-plan.md template). Generated bytes are order-independent/deterministic (ADR-0014); authored frontmatter follows profile DECLARATION order (ADR-0011 append-slot, no global re-sort).
- resource value = resource_base + concept repo-relative path (one slash at join, URL-encoded segments, .md preserved); empty resource_base omits it; stamped once at lore new, round-trips verbatim; never on index/sub-index files.

ADR amendments: ADR-0006 (primary inversion; RETAIN the §5 summary-length heuristic as a lore built-in since it is not declaratively expressible), ADR-0011 (append-slot order = profile field order), ADR-0013 (introduce .lore/profile.toml; resource_base is a profile key — reconciles LORE-47 AC#3), ADR-0007 (tiered validation + required-sections profile-driven). Extends LORE-15 (build validators from the profile); feeds LORE-19/LORE-20.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented on feat/lore-46-declarative-profile (commit 6bd7bdc). Inverted ADR-0006: new src/core/profile.ts loads+compiles .lore/profile.toml (Bun.TOML, hand-rolled grammar validation mirroring config.ts, injectable root, zero-config) into an immutable Profile carrying generated per-type Zod + Draft-7 JSON Schemas, LOWER-KEBAB slugs, and the canonical key order. schema.ts/concept.ts/core/validate.ts/scaffold.ts/template.ts and the init/new/validate commands thread the compiled Profile via an explicit param defaulting to the memoized built-in defaultProfile() — so any caller not opting into a custom profile is byte-for-byte unaffected (proved: all pre-existing tests + scaffold/init schema goldens pass unchanged).

Key decisions: (1) supersedes/superseded_by keep their string|list union as lore-reserved coupling fields with a built-in validator (the grammar's kind cannot express a union — AC#5 expressiveness limit, same precedent as the §5 summary heuristic), which also keeps their JSON schema byte-identical. (2) Editor schema filename keeps the .schema.json suffix with the slug as stem (Reference->reference.schema.json unchanged; QA Plan->qa-plan.schema.json) — renaming to <slug>.json would break every committed modeline in docs/; read AC#7's 'qa-plan.json' as naming the slug. (3) typeDirectory stays a lore built-in convenience map (not in the finalized grammar).
