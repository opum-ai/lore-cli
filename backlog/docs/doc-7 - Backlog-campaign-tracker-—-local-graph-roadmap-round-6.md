## Treehouse worktree and branch policy

- Treehouse v2.1.0 is installed. Repository config is `treehouse.toml` with `root = "../"` and `max_trees = 4`; its pool is beside the repository on the same external filesystem. Do not use the default user-home pool for this repository.

- Before dispatch, run `treehouse status --json` and reconcile every lease against this tracker. An unmatched campaign lease is an anomaly; never take it over or return it silently.
- Acquire only with `treehouse get --lease --lease-holder "lore-cli/<TASK>" --json`. Record the returned path, lease ID, holder, pinned base SHA, and branch before edits.
- Pin every new task tree to the verified integration-base SHA before branching. Use one task per branch with `feature/<lowercase-task-id>-<short-slug>`; never stack unrelated tasks or reuse an in-flight branch.
- Keep task dependencies and build caches inside the leased tree. Do not share or symlink dependency directories and never use `git stash` across worktrees.
- Retain the lease through implementation, verification, review, and authorized delivery. Never return a dirty or unfinished tree.
- Return only after settlement and only with both guards: `treehouse return --force --if-lease-id <id> --if-lease-holder "lore-cli/<TASK>" <path>`. Verify the exact target and authorization first because return resets the tree.
- `treehouse enter` attaches to an existing tree but does not acquire it. `treehouse prune` is dry-run-only unless the user separately authorizes deletion; leased trees are never prune candidates.
